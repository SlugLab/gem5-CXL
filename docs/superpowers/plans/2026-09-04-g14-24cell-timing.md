# G14 24-Cell Host and CIRA Timing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a hash-bound 24-row G14 bundle containing host-inline region time and CIRA device runtime for six workloads at four CXL latencies.

**Architecture:** Keep the current matched-replay measurement mechanism, but make host and CIRA evidence independently resumable so M2NDP availability cannot block them. Add a bounded lazy PageRank trace for the accepted G14 graph, reuse hash-valid non-graph traces, and run a fresh background campaign whose dynamic CIRA span is distinct from an optional inactive fixed-control replay.

**Tech Stack:** Python 3 `unittest`, C++17 matched replay, gem5 24.1 timing simulation, canonical/lazy trace schemas, JSON/CSV with SHA-256 evidence.

- [ ] **Step 3: Implement the focused PageRank adapter**

Define:

```python
EXPANDERS = {"pr_spmv_iteration": expand_iteration}

def build_bundle_from_csr(
    csr_root: Path, outdir: Path, *, graph_path: Path,
    graph_sha256: str, graph_scale: int = 14, iterations: int = 20,
) -> dict:
    graph_path = graph_path.resolve()
    if sha256_file(graph_path) != graph_sha256 or graph_scale != 14:
        raise PageRankTraceError("G14 graph identity differs")
    arrays, node_count, edge_count = write_csr_and_score_images(
        csr_root.resolve(), outdir.resolve()
    )
    invocations = tuple(
        make_iteration_invocation(index, node_count)
        for index in range(iterations)
    )
    primitive_records = sum(
        primitive_count(invocation, arrays)
        for invocation in invocations
    )
    meta = page_rank_metadata(
        graph_path, graph_sha256, graph_scale, iterations,
        node_count, edge_count, arrays,
    )
    lazy.write_bundle(
        outdir, meta, arrays, invocations,
        {"primitive_records": primitive_records},
    )
    return evidence_record(outdir, graph_path, arrays, invocations)
```

The bundle maps `in_offsets.u64`, `in_neighbors.i32`, `out_degree.u32`, and
two score buffers. Use raw `f32` operations after every arithmetic step to
preserve the application accumulation order. Create 20 invocations, one per
iteration, and store the exact primitive-record count. Bind graph path hash,
CSR file hashes, generator hash, scale, and iteration count in metadata. Keep
`graph_sha256` as the source graph identity; the schema-owned `input_sha256`
is the independent hash derived from the CSR and initial score images by
`lazy.initial_state_sha256()`.

Register the module in `lazy_workload_registry._MODULES`. Implement
`expand_slice`, `fixed_controls`, and `fast_forward` so timing-window
materialization does not expand unrelated iterations into retained output.

```python
REPLAY_STAGES = ("host_inline", "cira_runtime")

def execute_replay_stage(
    state, identity, workload, latency, stage, registry_cell,
    calibration, *, root, launcher, state_lock,
):
    # Validate and run outside the lock. Commit only this stage's result while
    # holding state_lock, then atomically replace state.json.
    result = launcher(
        stage=stage, workload=workload, latency=latency,
        cell=registry_cell, calibration=calibration,
    )
    with state_lock:
        commit_stage_result(state, identity, workload, latency, stage, result)
        atomic_write_json(Path(root) / "state.json", state)
    return result
```

Each stage gets its own monotonically numbered attempt directory, evidence
file, hash record, status, and error. Commit state immediately after each
stage. Add `--systems` with choices `host-inline,cira`, `host-inline`, and

different coordinates concurrently. All state mutations and `state.json`
